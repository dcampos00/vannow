# Headless CAD Mesh Rendering & Verification Architecture

This reference explains the mathematical foundation, performance optimizations, and implementation details of headless 3D CAD mesh rendering for automated design verification.

---

## 1. Why Matplotlib `mplot3d` Fails for CAD Enclosures

Standard Matplotlib 3D (`mpl_toolkits.mplot3d`) uses a naive **Painter's Algorithm**:
1. Triangles are sorted strictly by the Euclidean distance from the camera to the triangle centroid.
2. Polygons are then drawn sequentially from furthest to nearest.

### Fatal Flaws on Non-Convex Geometry
* **Cyclic Overlaps:** In hollow boxes, interior standoffs, and screw holes, triangle $A$ can be partially in front of $B$, while $B$ is in front of $C$, and $C$ is in front of $A$. Centroid sorting breaks down completely.
* **Lack of Z-Buffering:** Because there is no per-pixel depth test, back faces frequently draw over front faces, resulting in inside-out, transparent, or "broken" visuals.
* **Tessellation Clutter:** Calling `Poly3DCollection(..., edgecolors=...)` renders every Delaunay triangulation seam generated by OpenCASCADE across flat planar faces, cluttering the image with spiderweb artifacts.

## 2. Software Z-Buffer Rasterizer Architecture

A vectorized software rasterizer implemented with pure NumPy and Pillow delivers **100% solid, artifact-free, sub-second renders** without requiring X11, EGL, or heavy GPU drivers.

## 3. Mathematical Formulation

### 1. Screen Projection
Given world vertices $V_{world}$ centered at origin, camera rotation $R = R_x(\theta_{elev}) R_z(\phi_{azim})$:
$$V_{cam} = R \cdot V_{world}$$
Scale to fit image dimensions $W \times H$:
$$\text{scale} = 0.82 \cdot \frac{\min(W, H)}{\max(\text{span}_X, \text{span}_Y)}$$
$$X_{screen} = X_{cam} \cdot \text{scale} + \frac{W}{2}$$
$$Y_{screen} = -Y_{cam} \cdot \text{scale} + \frac{H}{2} \quad (\text{inverted for pixel space})$$
$$Z_{screen} = -Z_{cam} \quad (\text{smaller/more negative is closer})$$

### 2. Screen-Space Backface Culling
With inverted $Y_{screen}$, standard counter-clockwise winding yields:
$$\text{cross2d} = (X_1 - X_0)(Y_2 - Y_0) - (Y_1 - Y_0)(X_2 - X_0)$$
$$\text{Visible} \iff \text{cross2d} < 0$$
This instantly culls $>50\%$ of all polygons without testing per-pixel depth.

### 3. Three-Point Blinn-Phong Lighting
In camera coordinates where $+Z_{cam}$ points towards the viewer:
* **Key Light:** $L_{key} = [0.45, -0.35, 0.82]^T$ (upper-right front)
* **Fill Light:** $L_{fill} = [-0.50, 0.40, 0.75]^T$ (upper-left front)
* **Half-Vector:** $H = \frac{L_{key} + V}{\|L_{key} + V\|}$ where $V = [0, 0, 1]^T$

$$\text{Intensity} = K_a + K_d \cdot \max(0, N \cdot L_{key}) + K_f \cdot \max(0, N \cdot L_{fill}) + K_s \cdot (\max(0, N \cdot H))^p$$
Recommended coefficients: $K_a = 0.28, K_d = 0.58, K_f = 0.20, K_s = 0.22, p = 20$.

### 4. Vectorized Barycentric Rasterization
For each triangle with bounding box $[X_{min}, X_{max}] \times [Y_{min}, Y_{max}]$:
$$w_0 = \frac{(Y_1 - Y_2)(x - X_2) + (X_2 - X_1)(y - Y_2)}{\text{denom}}$$
$$w_1 = \frac{(Y_2 - Y_0)(x - X_2) + (X_0 - X_2)(y - Y_2)}{\text{denom}}$$
$$w_2 = 1 - w_0 - w_1$$
A pixel is inside if $w_0 \ge 0 \land w_1 \ge 0 \land w_2 \ge 0$.
Interpolate depth: $Z_{frag} = w_0 Z_0 + w_1 Z_1 + w_2 Z_2$.
Update pixel if $Z_{frag} < Z_{buffer}[y, x]$.

## 4. Feature Crease Edge Detection

To render crisp technical CAD lines without triangulation noise:
1. Identify true geometric crease edges where the dihedral angle between adjacent faces exceeds $30^\circ$:
   ```python
   crease_mask = mesh.face_adjacency_angles > np.radians(30)
   crease_edges = mesh.face_adjacency_edges[crease_mask]
   ```
2. Depth-test crease edge midpoints against the rasterized Z-buffer:
   ```python
   if Z_mid <= Z_buffer[y_mid, x_mid] + tolerance:
       draw.line([(x0, y0), (x1, y1)], fill=dark_ink_color, width=1)
   ```
This ensures hidden internal crease edges are suppressed while visible profile and step lines are rendered sharply.
